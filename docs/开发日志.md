## 关于名字：为什么叫 LintLizard

**LintLizard** = **Lint**（毛絮、绒毛、灰尘）+ **Lizard**（蜥蜴）——
一只贴着地面爬行、专吃毛絮的蜥蜴，就是这台履带扫地机器人的形象。

* 名字定于 2026-09-15，仓库 `tw-xy/LintLizard`，**不改名**。
* 仓库名对应的是**整机**，不是当前阶段。现在仓库里只有第一阶段（遥控底盘）的功能，
  后面扫地、自动回充、避障导航、OLED/图传都往这个仓库里加，所以名字不会过时。
* 要区分版本时用 `LintLizard-v1`、`LintLizard-v2` 这种说法，仓库名保持不动。

## 1. 阶段一：娱乐与遥控（已完成 ✅）

### 1.1 数据链路

```
手机 Blinker 虚拟摇杆
     │ WiFi / 云
ESP8266-01S ──USART3(PB10/PB11,115200)──► CH32V307
                                            │ ① 行协议解析
                                            │ ② 差速解算
                                            ▼
                          USART1(PA9/PA10)=COM4 打印左右目标速度
```

### 1.2 引脚分配（依据：官方原理图 `PUB\CH32V30xSCH.pdf` 第 11 页 = VCT6-R1 板）

| 信号 | 引脚 | 板上位置 | 说明 |
|---|---|---|---|
| USART3_TX | PB10 | J4 第 1 脚（网络名 D15） | → ESP 的 RX |
| USART3_RX | PB11 | J4 第 3 脚（网络名 D14） | ← ESP 的 TX |
| GND | — | J4 第 7 脚 | 共地 |

**为什么选 USART3**：板上已被占用的资源 —— USART1(PA9/PA10)=WCH-Link 调试串口、PA13/PA14=SWD、
PA11/PA12=USB-HS、PB6/PB7=USB-FS+OLED、**PC6/PC7/PC8/PC9=内置 10M 以太网 PHY 差分线（接 HR911105A 网口）**、
PE9/PE7=用户 LED 跳线。USART3 的默认脚 PB10/PB11 完全空闲，且在 J4 上相邻、旁边就是 GND。

### 1.3 通信协议

115200 8N1，一行一帧，`\n` 结尾：

```json
{"x":-100,"y":100}
```

| 字段 | 范围 | 含义 |
|---|---|---|
| x | -100 ~ +100 | 左负右正（转向） |
| y | -100 ~ +100 | 后退负、前进正（油门） |

解析规则：只接受以 `{` 开头的行，只找 `x`/`y` 两个键，其它字段随便加。
ESP8266 上电时 74880 波特的启动乱码、Blinker 日志都会被安全丢弃（不占 err 计数以外的任何资源）。

### 1.4 差速解算

```
死区(±4%) → 指数曲线(可配) →  l = y + x ,  r = y - x  → 归一化 → 千分比输出(±1000‰)
```

归一化的作用：前进 100 + 右转 100 时 l=200/r=0，两边等比缩放到 l=1000‰/r=0‰，
**转向比例不失真**（不做归一化就会削掉一边、转角变化）。

### 1.5 非阻塞架构

* `BSP_Millis()`：TIM2 1ms 中断提供唯一时基；`BSP_Every(&last, period)` 做软定时器
* 主循环按 10ms（控制）/ 20ms（电调）/ 100ms（打印）/ 1s（统计）分片，**没有任何 `Delay_Ms()`**
* USART1/USART3 全部中断 + 环形缓冲；连 newlib 的 `_write()` 都重定向到环形缓冲，误用 `printf` 也不会死等
* 三层失效保护：ESP 端 1s 无摇杆数据回中 → 链路 300ms 无有效帧判离线 → 底盘 300ms 无新指令输出归零

### 1.6 实测验证数据

摇杆方向（一次完整推杆的记录）：

| 推杆方向 | x | y | L | R | 判定 |
|---|---|---|---|---|---|
| 正上（前） | +12 | **+100** | +999 | +784 | ✅ 前进为正 |
| 正下（后） | +3 | **-100** | -1000 | -1000 | ✅ 后退为负 |
| 正左 | **-99** | +20 | -677 | +999 | ✅ 左为负 |
| 正右 | **+100** | +7 | +999 | -868 | ✅ 右为正 |
| 右到底 | +100 | 0 | **+1000** | **-1000** | ✅ 完美原地右转 |

链路质量（连续运行 20s）：

```
[stat] LINK-OK  frames=2971 (48/s)  err=0  rx=41594  rxovf=0  txdrop=0
```

`frames` 单调递增从不归零 → 无重启；`err=0` → 一行都没解析错；两个缓冲零溢出。

### 1.7 遥控操作语义（怎么开、怎么停）

| 操作 | 行为 |
|---|---|
| 推摇杆 | 车按该方向**持续跑**（ESP 保持最后一次摇杆值，不会因为"按住不动"而掉速） |
| 把摇杆拖回中间 | **停车**（Blinker 摇杆只在手指移动时上报，拖动就会发 0,0） |
| 手机 / 云端断开 | ESP 检测到 `Blinker.connected()==false` → 自动归零 |
| 串口断了 / 主控异常 | CH32 侧 300ms 链路超时兜底 → 输出 0 并打印 `FAILSAFE` |

> ⚠️ 注意：**手指离开但没把摇杆拖回中间，车会保持最后速度继续跑**（"定速"语义）。
> 这是 Blinker 摇杆组件"事件式上报"的固有特性，不是 bug。
> 想要"按住才走、松手立停"的手感，要么换成局域网网页摇杆（能拿到触摸抬起事件），要么加"急停按钮"。

**实测验证（2026-09-15）**：改完后按住推杆 8 秒，`y` 稳定在 **+100** 从不归零，
脉宽保持 **1999/1943µs**，`frames` 单调递增（932→1268，48 帧/秒）、`LINK-OK` 全程稳定 → **"跑几秒就停"已解决**。

停车也一并验证：推住 3.5 秒（脉宽 1999/1909µs 不掉速）→ **把摇杆拖回中间** → `y` 立刻回 0、脉宽回 **1500/1500µs** → 再推又能启动。
开关车三段动作（开 → 停 → 再开）全部实测通过。

## 2. 阶段二：电调输出（信号层已验证 ✅，轮子转向待确认）

### 2.1 引脚

| 信号 | 引脚 | 板上位置 | 目标 |
|---|---|---|---|
| TIM3_CH1 | **PA6** | **J4 第 29 脚（丝印 D4）** | 左电调 信号线 |
| TIM3_CH2 | **PA7** | **J4 第 31 脚（丝印 D3）** | 右电调 信号线 |
| GND | — | J4 第 7 脚 | 两个电调的黑线 |

接线纪律（重要）：

1. **电调红线（BEC 5V/6V 输出）不接板子**，悬空包好
2. 电调动力电走**电池**（2S/3S 锂电），不要从板子 5V/3.3V 取
3. 电调 GND 必须与板子 GND 相连（信号要有参考电平）
4. 上电顺序：**先给板子上电**（程序跑起来输出中位）→ 再给电调上电池（电调读中位自检）

### 2.2 信号格式

标准 RC 有刷电调：**50Hz（20ms 周期）**，脉宽 `1000µs = 满倒车`、`1500µs = 中位(停)`、`2000µs = 满前进`。
上电后 3 秒（`MOTOR_ARM_DELAY_MS`）强制保持中位，给电调自检/解锁用。

### 2.3 寄存器级验证（openocd 直接读 TIM3）

```
CR1  = 0x81      CEN + ARPE
CCER = 0x11      CC1E | CC2E（两路输出使能）
PSC  = 0x5F(95)  96MHz / 96 = 1MHz → 1 计数 = 1µs
ARR  = 0x4E1F    19999 → 20ms = 50Hz
CCR1 = 0x5DC     1500µs（左，中位）
CCR2 = 0x5DC     1500µs（右，中位）
```

不用示波器也能自测：万用表直流电压档量 PA6/PA7 对 GND —— 中位 ≈0.25V、满前进 ≈0.33V、满倒车 ≈0.17V。

### 2.4 推杆实测（日志 `logs\serial_20260915_001224.log`）

| 时刻 | 动作 | x | y | L | R | 脉宽 | 判定 |
|---|---|---|---|---|---|---|---|
| 0.1s | 松手 | 0 | 0 | 0 | 0 | **1500/1500 µs** | ✅ 中位 |
| 4.1~6.2s | 推前 | ≈0 | +100 | +1000 | +1000 | **2000/2000 µs** | ✅ 满前进 |
| 11.7~12.7s | 推后 | -7 | -100 | -999 | -868 | **1001/1048 µs** | ✅ 满倒车 |
| 20.0~22.6s | 再推前 | ≈0 | +100 | +1000 | +1000 | **2000/2000 µs** | ✅ 复现 |
| 24.6~25.6s | 再推后 | -5 | -100 | -999 | -904 | **1001/1048 µs** | ✅ 复现 |

## 3. 踩过的坑（下次直接看这节）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | `.ps1` 脚本报"字符串未终止/意外标记" | Windows PowerShell 5.1 把**无 BOM 的 UTF-8 .ps1 当 GBK 解**，中文串把引号吃掉了 | 脚本里的字符串只用 ASCII（中文只留在注释外的地方/改成英文注释） |
| 2 | openocd 报 `couldn't open D:WCH_CH32V307_EVTprojects...` | openocd 的 `-c` 参数由 **Tcl 解析**，Windows 路径的反斜杠被当转义（`\b` 变退格） | 路径写成**正斜杠** `D:/.../x.elf` |
| 3 | 脚本一调用 openocd 就抛 `NativeCommandError` | openocd 把 banner 写到 **stderr**，而脚本设了 `$ErrorActionPreference='Stop'` | 调用前后临时设 `'Continue'`，用 `$LASTEXITCODE` 判断成败 |
| 4 | Arduino 开发板管理器装 ESP8266 包总是超时 | **Arduino CLI 不读系统代理/环境变量**，直连 GitHub 被打断 | 写 `%LOCALAPPDATA%\Arduino15\arduino-cli.yaml`：`network.proxy: http://127.0.0.1:7897` |
| 5 | 单独供电时点灯 APP 永远"不在线"，插上烧录器就在线 | ESP8266 连 WiFi 瞬时吃 **300~500mA**，弱电源直接塌陷 → 反复重启 | 独立 3.3V（≥500mA，5V+AMS1117-3.3），模块旁并 470µF+100nF；**USB-TTL 的 3.3V 带不动** |
| 6 | 用了带 `-5G` 的 5GHz SSID，怎么都连不上 | ESP8266 **只支持 2.4GHz** | 换成 2.4G 的 SSID |
| 7 | 烧录后 COM4 全是乱码，所有波特率都不对 | WCH-Link 的串口桥没跟目标对上（波特率本身没错：57600~921600 全扫过，只有 115200 正常） | **复位一次**（板上 S3 或 openocd reset）即恢复；判断依据：CPU halt 住后数据立刻归零 → 数据确实来自芯片 |
| 8 | COM4 突然消失，设备管理器里状态 `Unknown` | 板子断电/USB 掉枚举 | 插回 USB；下电后 COM4 消失是正常现象 |
| 9 | 原理图 PDF 文字读不出来 | Altium 导出的 PDF 文字被打散成单字符，按坐标拼不可靠 | 用 pypdfium2 **高倍渲染成图片**再读；或直接看关键区域的裁剪图 |
| 10 | Blinker 库编译报警告一大堆 | 库自身 `-Wwrite-strings` / `WiFiServer::available` 已废弃 | 与我们无关，忽略；我们自己的文件是 0 warning |
| 11 | ESP 上电串口先吐一段乱码 | ESP8266 ROM 用 74880 波特率打印启动信息 | 协议解析器只认 `{` 开头的行，自动丢弃 |
| 12 | 一次性命令里写 Windows 路径给原生程序，反斜杠会被吃掉 | PowerShell 向原生程序传参时的转义/引号处理 | 尽量用 `-File 脚本.ps1` 方式调用，路径在脚本内部处理 |
| 13 | 单独供电时 ESP 完全不启动（蓝灯不亮、串口无输出），插烧录器就正常 | **EN(CH_PD) 悬空** —— 我们这块模块没有可靠上拉（官方 ESP-01S 图上 R2 10K 是有的，但不是所有模块都焊/都有效）；另外蓝灯是接在 TXD/GPIO2 上的**数据灯**，不是电源灯 | **EN 直接接 3.3V**；判断模块死活看串口，不看灯 |
| 14 | 推杆后车**跑几秒自己停** | ESP 里"1 秒没收到摇杆数据就回中"的失效保护，把"按住不动"误判成"松手"（**Blinker 摇杆只在手指移动时上报**） | 改成保持最后值 + `!Blinker.connected()` 才归零；停车 = 把摇杆拖回中间 |


## 7. 激光雷达：YDLIDAR X2 兼容（数据链路 + 电脑点云 + 前向避障 ✅）

### 7.1 供电与接口（按原厂数据手册）

X2 的 4P 接口顺序是 **M_CTR / GND / Tx / VCC**。以 VCC 为第 1 脚往另一端数：

| 以 VCC 为起点 | 信号 | 接到哪里 |
|---|---|---|
| 1 | VCC | 独立 5V（启动瞬时峰值约 1A） |
| 2 | Tx | WCH-LinkE 的 **RX** |
| 3 | GND | 电源负极 + WCH-LinkE GND，必须共地 |
| 4 | M_CTR | 3.3V（或 0–3.3V / 10kHz PWM 调速）；**不是 RXD** |

> 卖家常把第 4 脚标成 RXD，这是错的。原厂 X2 数据手册第 3 页图 3 / 表 3 写的是 `M_CTR`。

![X2 雷达产品图](images/20260919_16_lidar_x2_product.png)
![雷达接线实拍](images/20260919_18_lidar_wiring.png)

### 7.2 电脑端验证结果

链路：`X2 Tx → WCH-LinkE RX → USB → COM6 @115200 → EaiLidarTest`。

| 验证项 | 实测结果 |
|---|---|
| 原始串口读取 | 3 秒 28615 字节，510 个 `AA 55` 帧头，约 9538 B/s |
| EaiLidarTest | 7.8 Hz / 4.18 K/s / 387(327) 点 |
| 2.56m 固定点 | 50 点，Min/Max 2559/2564，Std 1.5mm |

![EaiLidarTest 点云成功](images/20260919_22_eailidartest_com6_success.png)

### 7.3 踩坑：串口“打开成功”但读不到字节

* 现象：FTDI COM5 回环正常，EaiLidarTest 提示 `Automatic connection successful`，但 3 秒读不到一个字节，随后报 `Lidar disconnection` / `Operation timed out`。
* 根因：FTDI 的 RXD 没有真正接到 X2 的 Tx；卖家的“第 4 脚 RXD”标注也具有误导性。
* 解决：改用 WCH-LinkE-R0-1v3 的串口。Windows 识别为 `WCH-Link SERIAL (COM6)`，115200 直接读到 `AA 55` 数据。
* 结论：**不要只看“串口打开成功”**。用原始字节读一次最可靠；能读到 `AA 55` 才说明 Tx、GND、波特率都对了。

### 7.4 0° 正前方定义

原厂手册明确：**X2 的 0° 零方向在电机正前方**，也就是从旋转中心指向电机/接插件凸出的那一侧；角度顺时针增大。

![X2 零方向定义](images/20260919_x2_zero_direction.png)

装车时雷达 0° 要朝车头。若实际安装不是 0°，可改 `App/app_config.h`：

* 雷达装反 180°：`AVOID_FRONT_OFFSET_CDEG = 18000`
* 车头在雷达 90° 方向：`9000`
* 车头在雷达 270° 方向：`27000`

### 7.5 前向避障实测（2026-09-19）

固件：`App/app_avoid.c` + `App/app_radar.c`，`AVOID_ENABLE=1`。测试时履带悬空，雷达接 CH32 PA3，COM4 读数如下：

| 操作 | `front` | `avoid` | 左右脉宽 | 结论 |
|---|---|---|---|---|
| 前方约 1m，推前进 | 1026–1049 mm | `CLEAR` | 2000/2000 µs | ✅ 满速前进 |
| 前方约 45–55cm，推前进 | 435–549 mm | `SLOW` | 约 1735–1970 µs | ✅ 随距离线性降速 |
| 前方约 22–30cm，推前进 | 221–307 mm | `STOP` | 1500/1500 µs | ✅ 前进被禁止 |
| 前方约 22cm，推后退 | 223 mm | `STOP` | 1000/1000 µs | ✅ 倒车仍允许 |
| 前方约 22cm，推右转 | 224 mm | `STOP` | 2000/1000 µs | ✅ 原地转仍允许 |
| 雷达拔掉/无数据 | 0 | `FAULT` | 1500/1500 µs（前进） | ✅ 失效保护 |

链路质量：`rx≈9400 B/s、ok≈168/s、csErr=0、fmtErr=0、ovf=0`。

> 说明：`front=0` 表示当前窗口没有有效前向回波，不是距离 0mm。避障只使用前向扇区，左右扇区目前只做预留。

### 8.2 目前踩过的坑

* **Imager 2.0.11.1 崩溃**：错误在 `libstdc++-6.dll`，异常码 `0x40000015`；连续两次都在写卡阶段退出。换 Imager 1.9.6 + 已缓存镜像后写入成功。
* **读卡器掉线**：崩溃后 USB 读卡器从 Windows 消失；换 USB 口并让火绒信任 `D:\imager` 后恢复。
* **bootfs 无盘符**：写卡后 Windows 只看到两个分区，但 FAT32 `bootfs` 没有盘符；需要在磁盘管理里手动分配。
* **SSH 默认没开**：Raspberry Pi OS Lite 首次启动后 22 端口关闭；需要在 HDMI 控制台执行 `sudo systemctl enable --now ssh`。
* **Clash fake-IP**：`lintlizard.local` 被解析到 `198.18.0.164`，SSH 被 Clash TUN 当外网流量接走；实际用 `192.168.1.213` 直连。
* **中文 SSID**：Linux 控制台没有中文输入法，`妙妙喵-2.4G` 很难手动输入；已改为英文 2.4G SSID。注意路由器实际广播名是 `miaomiaomao2.4G`（末音节是 `mao` 不是 `miao`），5G 才是 `miaomiaomiao5G`，配 WiFi 时别打错。

1. ✅ 公钥免密登录已装好；✅ WiFi 已连 `miaomiaomao2.4G`（`192.168.1.5`，autoconnect）。
2. AAT-1 接 CH32：`GND → J4-7`、`RX → J4-1(PB10)`、`TX → J4-3(PB11)`、`5V` 不接。
3. Pi 侧启用 UART、关闭串口控制台，Pi 3B+ 建议加 `dtoverlay=disable-bt`。
4. CH32 侧把雷达原始数据转发到 USART3，同时接收 Pi 的 `{"x","y"}` 运动命令。
